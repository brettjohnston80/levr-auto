# Dealer-installed options: where the flag lives (proposal, 2026-10-16; nothing built)

Brett's pass 4 decision 4: keep the "dealer-installed" information, because dealer-installed add-ons matter for the add-on removal flow and for negotiation.

## What the research data has today

| Source | What marks dealer-installed | Count |
|---|---|---|
| GM option names (GMC, Buick, Cadillac) | GM's own "LPO" code (Limited Production Option: dealer- or port-installed accessories) at the start of the name, e.g. "LPO, Wheel locks, set of 4" | GMC 1,508, Buick 176, Cadillac 1,364 option items (all files, still present after pass 4) |
| GM package notes | "(dealer-installed LPO accessory package)" / "dealer-installed (LPO); " in package contents | GMC 319, Buick 44, Cadillac 355 entries in the **pass 3** files. Pass 4 removed them from the contents, but the pass 3 files keep them. |
| Other makes | Only package notes the import already strips (Honda 29, Hyundai 10, Ford 5, Toyota 2 mention "dealer-installed"), plus loose words like "accessory" or "by Mopar" | No reliable per-option flag. **Not inferred.** |

## Proposal

**1. Where it lives:** a new column, `configurator_options.dealer_installed boolean not null default false`. This is a migration, which Brett runs.
- It's set per option row, so a package-only item inside a dealer-installed package is flagged too.
- Kept on the option, like `availability` and the package fields, so every view reads one fact.

**2. How it's set at import** (a tested rule in the mapping/parse step, logged like the corrections):
- **GM names:** an option whose name starts with "LPO" → `dealer_installed = true`. The stored name keeps GM's text as received.
- **GM packages:** pass 4's removed package flags are restored from a small reviewed data file, `data/configurator-dealer-installed-packages-2026-10.csv` (make, model, trim, year, package). It's generated by comparing pass 3 with pass 4 (the 718 entries above), and its package rows' options get the flag.
- **Other makes:** a later Cowork pass adds an explicit dealer-installed marker per option from each brand's US configurator ("dealer-installed", "port-installed", "accessory installed by dealer"). Nothing is inferred from words like "accessory".
- **Then re-import:** Buick and Cadillac (live; swapped after a diff showing only the flag changed), and GMC (not live yet).

**3. Where it's shown:**
- **Agents** (build-preferences card on `/internal/outreach`, and the Log Offer add-on lines): a "Dealer-installed" tag on any wanted option or package that's dealer-installed. When an offer itemizes such an add-on, the agent sees it's removable and negotiable.
- **Customers** (Your Car, the configurator rows, Review): a small "Dealer-installed" tag next to the price.
  - **Optional:** on an offer, a dealer-installed add-on gets the existing "Request removal" action shown first.
- **Display name:** customers would see "Wheel locks, set of 4" with the tag, rather than GM's "LPO, Wheel locks, set of 4". The stored name stays as received.

**4. Customer-facing wording to approve:**
- the tag: **"Dealer-installed"** (alternative: "Installed by the dealer");
- dropping the "LPO, " prefix from displayed names when the flag is set (yes / no).
