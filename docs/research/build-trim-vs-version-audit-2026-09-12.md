# build.trim vs. build.version mismatch — full-catalog audit (2026-09-12)

Follow-up to the RAV4 XLE 2026 investigation (`rav4-xle-trim-truncation-investigation-2026-09-10.md`), which found MarketCheck's own `build.trim` field silently drops the "Premium" modifier from RAV4 XLE Premium and confirmed Levr's own sync code passes that field through verbatim with no cross-check. This is a sizing pass across the whole catalog, requested to find out how widespread that pattern is. **Investigation only — nothing was changed.**

## Method and an important limitation

Levr's live `listings` table isn't reachable from this session (no database credentials), so this audit can't confirm exactly which make/models currently have real synced rows. As a proxy, it checked MarketCheck's own live API directly — the same third-party source Levr's sync consumes — against **all 328 distinct make/model pairs** in Levr's researched Matchmaker dataset (`matchmaker-vehicle-dataset-2026-v20.csv`, 36 makes), using that dataset's own trim names as the "correct" vocabulary to compare against. For each pair: pulled MarketCheck's live trim facet (real national new-car listing counts per trim), flagged any facet trim that didn't exactly match a canonical trim, then pulled a live sample listing (`include_build_object=true`) for the higher-count flags to directly compare `build.trim` against `build.version` and the dealer's own listing heading.

**Coverage caveat:** MarketCheck's API quota was exhausted partway through (the tool started returning `429 Monthly API quota exhausted`). Facet-level data was gathered for 313 of the 328 pairs; the other 15 were never queried at all (listed below). Of the pairs with a flagged mismatch, roughly half (125 of 257 individual flags) got a live sample pull to confirm the pattern before quota ran out — the rest are facet-level candidates only, not yet confirmed. Everything below is labeled accordingly; nothing here should be read as a final, exhaustive count.

## Headline numbers

Of the 328 pairs: 43 have no active new-car listings right now, 111 came back completely clean (every live trim matched the canonical name exactly), 15 were never checked (quota), and **159 pairs — roughly half of everything with real listings — showed at least one candidate mismatch**, totaling 257 individual flagged trim values (125 confirmed via a live sample, 132 still facet-level-only).

This is not a RAV4-specific issue. It is a broad, recurring characteristic of MarketCheck's `build.trim` field across many manufacturers.

## The core pattern: a dropped modifier (confirmed on ~20+ make/models)

The exact RAV4 shape — `build.trim` strips a real word or code that `build.version` and the dealer's own heading both correctly retain — was confirmed, with a live sample, on a wide range of brands. A sample of the highest-volume confirmed cases:

Mercedes-Benz GLE (drops "4MATIC" and the space in "GLE 350"), BMW X5/X3/X7/3 Series/7 Series/iX3/X1/Z4 (drop "xDrive"/"sDrive"/"eDrive" prefixes and suffixes across nearly the whole lineup), Subaru Outback and Forester (the turbo "XT" and "Hybrid" modifiers appear to be folded into the plain trim, at 14,000+ listings each), Mazda CX-5/CX-50/CX-90/CX-70 (drop the "2.5"/"2.5 Turbo"/"3.3 Turbo"/"Hybrid" engine prefix, tens of thousands of listings), Toyota Highlander, Tacoma, Corolla Cross, Grand Highlander, and bZ (drop "Hybrid" or drivetrain/package qualifiers — Tacoma's "TRD Off Road" bucket alone mixes gas and Hybrid at 14,000+ listings), Honda CR-V (drops "Hybrid" from all four hybrid trims, one bucket at 7,546 listings), Genesis G70/G80/GV70/GV80/GV80 Coupe/G90 (drop the "2.5T"/"3.5T" engine designator across nearly every trim in the brand), Lexus RZ/TX/NX (drop the "350e/450e/550e" or "h"/"+" powertrain suffix — NX's entire hybrid lineup appears to have no distinct facet bucket at all), Chevrolet Trax (drops the "1"/"2" tier prefix from "1RS"/"2RS", merging two real trims), Buick Encore GX (drops FWD/AWD), Land Rover Discovery/Range Rover/Range Rover Sport/Evoque (drop "P300"/"P400"/"P530"/"P250" powertrain codes), Volvo XC40/EX30/EX60/EX90 (drop "B4"/"B5"/"B6"/"T8"/motor-count prefixes), Ford Escape (spells out "PHEV" differently) and VW ID.4 (drops "AWD"). In every one of these, `build.version` (and usually the heading) has the correct, complete name — meaning the fuller field genuinely works as a fallback here.

## Worse than RAV4: total collapse to a generic placeholder

Several cases go further than dropping a modifier — `build.trim` returns a meaningless generic value for the entire model, discarding the real trim completely:

Mercedes-Benz is the standout brand for this: EQE SUV (100% of 369 listings show `build.trim="Base"`), EQS and EQS SUV (~99%), GLS (88%), CLA (91%), and GLC (72%, 18,783 of 26,140 listings) all collapse to "Base" — and SL's entire trim facet is just "Mercedes-AMG"/"Mercedes-Maybach," with no real SL 43/55/63 trim appearing anywhere. Elsewhere: Audi Q3 (98% show "Base" instead of its only real 2026 trim, "S line"), Audi RS Q8 (100% "Base"), Genesis G90 (77%), Jeep Cherokee (`build.trim="Base"` instead of "Cherokee"), Polestar 4 (100% "Base"), BMW X5 M and X6 M (`build.trim` is just the model name, "X5 M"/"X6 M," instead of the real trim "Competition"), and Chevrolet Corvette (`build.trim` only ever contains the equipment-package code like "2LT"/"3LZ," dropping the actual model name — Stingray, Grand Sport, Z06 — entirely). `build.version` correctly recovers the real trim in most of these.

## Worse still: build.version isn't a universal fix

For a fix to just "read build.version instead," it would need to reliably be there and be correct. It isn't, always:

Honda Prelude — 100% of listings show `build.trim="Base"` (not even a real trim; Prelude is hybrid-only, real trims are "Hybrid"/"Hybrid Two-Tone"), and `build.version` is a literal empty placeholder, `"-"`. Audi RS e-tron GT and RS Q8 — `build.version` is also just `"-"`; only the dealer's own heading text has the real trim. Cadillac CT5 "Luxury" — both `build.trim` and `build.version` drop "Premium"; only the heading says "Premium Luxury." Mercedes G-Class "G580" — `build.version` drops "Technology," and the heading uses a third, different spelling again. Jeep Grand Wagoneer and Mazda3 — both fields omit "Edition" from "85th Anniversary Edition." Mazda CX-5's "S Preferred" bucket (14,467 listings) has the same problem: both `build.trim` and `build.version` drop the required "2.5" engine prefix; only the raw dealer heading is complete.

## MarketCheck sometimes introduces the error itself, not just relaying bad dealer data

Chevrolet Equinox EV is the clearest evidence of this: canonical trim is "LT2," and both `build.trim` and `build.version` show "2LT" — but the dealer's own listing heading correctly says "LT2." MarketCheck's own processing flipped it, it didn't just copy through a sloppy dealer listing. Cadillac Escalade ESV shows a related symptom — "Sport Platinum" and "Platinum Sport" exist as two separate facet buckets for what should be one trim, suggesting inconsistent internal normalization rather than a single clean rule.

## Not a MarketCheck bug: gaps in Levr's own canonical trim list

A meaningful chunk of flagged items turned out, on inspection, to be places where `build.trim`, `build.version`, and the dealer heading all agree with each other on a real trim name that simply isn't in Levr's own researched dataset yet — a research gap, not a sync bug. Examples worth a quick manual check on Levr's side: Hyundai Elantra's largest trim bucket (7,909 listings) is genuinely named "SEL Sport Plus" everywhere, not "SEL Sport Premium" as canonically listed; Honda Accord's Hybrid trims, Hyundai Kona's "Essential"/"SEL," VW Jetta's "GLI Autobahn," and Chevrolet Equinox's "LS" show the same shape. Chevrolet Colorado's largest bucket (8,647 listings) is a naming-convention mismatch rather than either kind of bug — MarketCheck spells out "Work Truck" where Levr's canonical trim is the abbreviation "WT," and the two vocabularies never intersect on their own.

## What wasn't checked

15 make/model pairs were never queried at all before the API quota ran out: Toyota Land Cruiser, Toyota Tundra, Toyota GR Supra, **Toyota RAV4 itself** (the original case — its number here is already established from the prior investigation, so this doesn't change that finding, but it means RAV4 wasn't re-verified as part of this specific pass), Volkswagen Jetta GLI, Volkswagen Golf GTI, Volvo V60 Cross Country, Volvo EX30 Cross Country, Volvo XC90, Mitsubishi Outlander Sport, Nissan Rogue, Porsche Panamera, Ram ProMaster, Subaru Impreza, and Tesla Model Y. A further 132 flagged candidates across the other pairs have facet-level evidence (an unrecognized trim name with a real listing count) but no live sample pull to confirm the exact mismatch shape. The highest-volume of these unconfirmed leads: GMC Sierra EV (100% of 1,050 listings show only the bare tier name, missing "Standard Range"/"Extended Range" entirely), Mazda CX-50's second-largest bucket, Mercedes-Benz GLC/SL (already strongly evidenced above but the very largest buckets weren't independently re-pulled), Porsche Taycan, Lexus RX and LX, and Land Rover Range Rover Velar. Re-running verification on these once MarketCheck's quota resets would close out the picture.

## Bottom line

This confirms the concern behind the RAV4 finding: MarketCheck's `build.trim` field is not a reliably complete trim name across the catalog. The failure isn't one bug with one shape — it ranges from a single dropped modifier word (recoverable from `build.version`) to total collapse into a meaningless placeholder like "Base" (also usually recoverable from `build.version`) to cases where `build.version` fails too (only the raw dealer heading is trustworthy) to at least one case where MarketCheck appears to introduce a new error beyond what the dealer's own text says. A real fix would need to reconcile `build.trim`, `build.version`, and the dealer heading against Levr's own canonical trim list per make/model, not simply swap which single MarketCheck field the sync reads — and would separately need to feed back the handful of real canonical-data gaps this pass surfaced. No such fix, and no change to Levr's own code or data, was made as part of this pass, per the explicit instruction to investigate and report only.
